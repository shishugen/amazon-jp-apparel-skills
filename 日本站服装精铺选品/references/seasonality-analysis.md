# 目标季节窗口季节性分析口径

## 目标

筛掉**目标窗口内**强季节款。服装里 T 恤、保暖衣、家居服容易季节性明显；基础衬衫、裤装、内衣通常更稳。但**不要靠常识下结论，一律用逐月数据算**。

默认窗口为**春夏秋 3–11 月**（`seasonality=three_seasons_spring_summer_autumn`）。冬季不卖但经营季稳卖的产品允许进入候选。需要严格全年口径时改 `strict_year_round`。

## 窗口定义（唯一开关 seasonality）

| 值 | 窗口 |
|---|---|
| `three_seasons_spring_summer_autumn`（默认） | 3–11 月，春3-5/夏6-8/秋9-11；排除冬季 12/1/2 月 |
| `strict_year_round` | 1–12 月全月 |
| `custom` | 读 `season_window_months`（1–12 整数数组） |
| 旧值 stable/strict/flexible | 自动回退全年，兼容旧参数 |

**窗口外月份不填 0、不参与 CV、峰谷比、稳定月数和评分**，仅在「季节性分析」表的「窗口外月份(排除)」列留档披露，让经营者判断空档期成本。

## 数据来源优先级

1. **竞品 ASIN 逐月销量**（`asin_sales_trend_*.xlsx`）——最贴近销售。
2. **关键词逐月搜索/购买量**（`keyword_trend_*.xlsx`）——ASIN 数据不足时用。
3. 两者都没有 → 标「数据不足」，按低分处理，不按稳定算。

脚本自动选：`asin_sales` 有数据就用它，否则用 `keyword_trend`。

## 计算

取最近 `history_months`（12 或 24）个月的序列，**先按窗口过滤，再计算**：

```text
CV（变异系数） = 总体标准差 / 均值      ← 只基于窗口内有效月份
峰谷比         = 最高月 / 最低月          ← 同上
稳定月数       = 落在均值 ±20% 区间内的窗口内月份数
有效月份数     = 窗口内数值 > 0 的月份数
```

缺失月份不填 0。窗口内有效月份少于 `max(3, round(6 × 窗口月数 / 12))`（全年=6，三季=4）→ `数据不足`。

## 判定（按窗口内 CV）

| 月度 CV | 判定 | 稳定性得分（25分） |
|---|---|---:|
| ≤ 20% | 目标季节稳定 | 25 |
| 20%–30% | 轻微波动，可考虑 | 20 |
| 30%–50% | 中等季节，降分 | 11 |
| > 50% | 强季节 | 4 |
| 数据不足 | 不按稳定算 | 8 |

辅助看峰谷比：>7 基本可判强季节，即使 CV 不高也要人工复核。

**单一峰值依赖**：即使窗口内 CV 低，若销量几乎全靠窗口内某一月份（如 8 月水着/夏季限定），必须标记季节性并降权，不得判稳定。冬季淡季不作为否决项。

## 历史实测参考（仅供参考，不是标准）

来自本机既往卖家精灵数据（全年口径）：

| 品类 | 关键词示例 | CV 区间 | 判读 |
|---|---|---|---|
| 裤装 | ズボン / カーゴ / チノ | 0.20–0.28 | 较稳 |
| 内衣 | 下着 | 0.21–0.31 | 较稳 |
| 家居服 | パジャマ | ~0.51，峰谷 6.6 倍 | 偏季节 |
| T 恤 | Tシャツ | ~0.89 | 强季节 |
| 保暖衣 | ヒートテック | ~1.31 | 极强季节 |

**这些是历史样本，不能替代本次导出数据。** 报告里只作为解释性背景，不参与打分。改用三季窗口后，强季节款的 CV 会明显下降（冬季塌陷月被排除），判读阈值不变。

## 常见误判

1. **把子 ASIN 销量加起来当父 ASIN** —— 颜色/尺码变体会重复计数，按父 ASIN 去重。
2. **用 30 天快照判全年** —— 不行，必须逐月。
3. **窗口内只有 2–3 个月数据就判稳定** —— 标数据不足（三季需 ≥4）。
4. **异常值拉高均值** —— 月销过万标记并排除，写进数据缺口。
5. **只看搜索量不看购买量** —— 趋势表里有月购买量时一并看，脚本主口径用搜索量（数据更完整）。
6. **把三季判稳说成"全年稳定"** —— 报告措辞必须是"目标季节窗口内稳定"，除非窗口=全年。
